# QA36 요격기 일제 출격의 명령 실행 대기

사용자 플레이에서 QA35 범위 이펙트는 정상으로 보고됐으나 요격기는 여전히 순차 출격했습니다. 실행 중인 QA35 DLL의 해시를 확인한 뒤 게임 메모리를 읽기만 하여 네이티브 명령 분기 코드를 대조했습니다. 게임에 명령을 보내거나 메모리를 쓰지 않았습니다.

네이티브13515의 명령 디스패처는 Unit+0xc9의 `order_wait`를 먼저 감소시키고, 이전 값이 0일 때만 8로 설정한 후 캐리어 명령을 실행합니다. 캐리어 공격 함수는 별도로 Unit+0x70의 `order_timer`를 사용하고 첫 출격 뒤 7로 설정합니다. QA35는 두 번째 값만 지워 추가 호출이 디스패처에서 막혔습니다. 이전 호스트 검사의 단순 출격 함수는 디스패처 대기를 구현하지 않아 이 오류를 잡지 못했습니다.

QA36은 원래 명령이 실제 첫 출격을 승인한 경우에만 같은 프레임의 추가 출격 호출에서 두 대기를 모두 0으로 설정합니다. 추가 출격이 거절되고 명령이 유지되면 두 대기를 복구합니다. 표적·사거리·비활성·정지 검사와 연결 목록 이동은 원래 게임 경로를 계속 사용합니다. 각 출격의 실제 내부/외부 목록 변화를 확인하며 최대 8기까지만 반복합니다. 체력·보호막 2배, 원래 4/8기 수용량, 생산 비용·시간, 성장 기록과 과거 발급 후보 보존은 QA35와 같습니다.

새 회귀 검사는 네이티브 디스패처의 감소/이전 값 검사/8로 재설정 분기를 재현합니다. QA35 헤더를 끼운 동일 호스트는 이 검사에서 실패해야 하며 수정본은 통과해야 합니다. 1~8기·부분 격납고·출격 속도 재능 조합·적/동맹/중립·첫 명령 대기·표적/사거리/비활성/정지 거절·추가 출격 중단 후 대기 복구를 검사합니다. 새 DLL의 실제 게임 출격은 사용자 플레이 확인 전까지 미검증입니다. 이펙트 정상 보고는 사용자가 확인한 범위에 한정하며 모든 효과·HD/SD·FPS 검증으로 확대하지 않습니다.
