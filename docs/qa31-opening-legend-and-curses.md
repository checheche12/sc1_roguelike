# QA31 첫 전설 꾸러미와 일반 저주 분산

여섯 본 캠페인의 확정 전설 선택을 첫 임무 시작의 첫 성장 선택으로 옮깁니다. 같은 종족의 서로 다른 유닛 전설 두 개를 묶은 꾸러미 네 개 중 하나를 선택합니다. 해당 캠페인에서 나중에 사용할 유닛도 후보에 포함하되, 두 효과 모두 그 캠페인 안에서 사용 가능한지 확인합니다. 공용 단독 전설은 시작 꾸러미에서 제외합니다.

중반 확정 전설 선택을 앞당긴 것이므로 캠페인 전체 보상 횟수와 경제 보상 다섯 번은 같습니다. 이후 일반 선택의 희귀도 확률과 비밀 임무의 일정은 유지합니다. 이미 제시한 후보 JSON과 확정 성장 스냅샷은 다시 뽑거나 덮어쓰지 않습니다. 첫 선택을 마친 기존 기록에는 전설을 소급 지급하지 않습니다.

일반 저주의 증가량을 낮추고, 기존 고급 등급의 ‘시간 가속’을 일반 등급의 공격·이동 속도 저주로 개편합니다.

| 저주 | 매번 더하는 증가량 | 3중첩의 누적 증가 |
| --- | --- | --- |
| 끝없는 증원 | +20%, +24%, +28%… | +72% |
| 군비 경쟁 | +8%, +12%, +16%… | +36% |
| 악마의 생명력 | +8%, +12%, +16%… | +36% |
| 시간 가속 | +5%, +6%, +7%… | +18% |

증원·공격력·체력의 각 회차 증가량은 QA30보다 20% 낮습니다. 공격·이동 속도는 각각 기본 속도에 합산합니다. 3중첩이면 공격 주기는 기본 주기의 1/1.18, 이동 속도는 기본의 1.18배가 됩니다. 마법 시전 속도는 올리지 않습니다. 네 저주의 선택 상한을 없애며, 실제 적 소유 추가 공세에만 적용합니다. 일꾼 공습의 기본 2·6·10기와 3중첩 제한은 유지하고, 조정한 증원 증가량을 적용합니다.

기존 ID와 저주 바이트 위치 16~19를 유지합니다. 255를 넘는 횟수는 기존 65워드 스냅샷의 사용하지 않던 중첩 공간을 사용하며, 이전 바이트 기록도 계속 읽습니다. 새 공속 카운터는 중첩 슬롯 28, 기존 세 카운터는 29~31입니다. 교범 중첩 슬롯 0~20과 겹치지 않습니다. 과거 후보 원문은 유지하고 새 후보의 등급·상한·설명을 갱신합니다. 실수 프레임 누적과 최소 1프레임 주기로 공속을 처리합니다.

검증은 임시 데이터베이스의 실제 관리자 선택·재접속·두 전설 획득·스냅샷 복원, 여섯 캠페인 보상 진행, Python/네이티브 전송과 프로덕션 네이티브 코드의 공격 주기·소유자 범위 검사입니다. 지도 63개의 체크포인트와 해시를 재검사하며 지도 파일은 바꾸지 않습니다. 자원 배치 검사는 동일 바이트인 이전 지도 검사에서 계승합니다. 게임 실행, 전투 밸런스 실측, 사용자 기록 초기화와 패치 설치는 수행하지 않습니다.

추가 공세 아비터와 다니모스는 같은 공세·소유자의 전투 병력을 따라 공격 이동합니다. 기존에는 탐지기만 지원 병력으로 분류해 아비터의 Follow(49)·ComputerReturn(163) 상태가 진격 복귀 대상에서 제외됐습니다. 아비터도 복귀할 수 있도록 하고, 다른 공세와 지원 유닛끼리 서로 따라가는 경우를 제외합니다. 호위 병력이 전멸하면 아비터는 플레이어의 현재 기지로 진격합니다. 스테이시스 시전과 초기 은폐 오라 설정은 중단하지 않으며, 원래 지도 병력은 명령하지 않습니다. 명령 번호는 [BWAPI Order 정의](https://github.com/bwapi/bwapi/blob/main/bwapi/include/BWAPI/Order.h)를 대조했고, 실제 게임에서 보고된 정지 현상의 원인 확정은 추가 플레이가 필요합니다.

비행 군체 화력 교범은 가디언·쿠쿨자(가디언)의 공격력을 중첩당 +3에서 +6으로 올려 뮤탈리스크와 맞춥니다. 다른 저그 공중 유닛의 +3, 공격 간격 -4.5%와 최대 4회 제한은 유지합니다. 4중첩은 가디언 공격력 +24이며 아군 소유에만 적용합니다. 기존 후보 원문을 보존하면서 이후 후보 설명을 갱신하는 검사도 포함합니다.

범위가 커진 스톰·EMP 폭발·인스네어 구름·스테이시스·마엘스트롬·다크 스웜·디스럽션 웹·아콘 타격과 전설 이레디에이트의 기존 애니메이션을 렌더링 단계에서 확대합니다. 무기의 실제 소유자별 반경, 지속 장판의 가로·세로 판정과 이레디에이트 전염 계보를 사용합니다. 새 병력·피해·마법·이펙트 스프라이트를 생성하지 않으며 기존 그림의 위치 좌표만 바꿉니다. 이레디에이트 대상의 몸체와 체력 막대는 확대하지 않습니다.

[SAMASE API44](https://github.com/neivv/samase_plugin/blob/c01a88f00b1aaf6286f96940b0f04498cea6c7b7/src/lib.rs)의 이미지 그리기 훅과 DrawCommands·VertexBuffer 변수를 사용합니다. [공개 DrawCommand 구조](https://github.com/neivv/aise/blob/master/bw_dat/src/bw/structs.rs)와 지원 엔진 13515의 보관된 읽기 전용 명령어에서 버퍼 위치를 대조했습니다. 한 이미지의 모든 기하 정보를 검사한 뒤 새로 추가한 정점의 XY만 확대하며 텍스처 좌표·색상·셰이더 값은 보존합니다. 재할당한 정점 버퍼, 여러 이미지가 공유하는 배치, 배율·원점·잘못된 기하 정보의 원자적 거부를 모의 검사합니다. 렌더링 스레드는 별도 불변 정책을 읽고, 시뮬레이션 쪽에서 소유자와 장판을 갱신합니다. 중립 색상의 타격 효과도 시전 출처로 판별하며 출처가 겹쳐 모호하면 원래 연출을 유지합니다.

이동 속도 저주는 네이티브 최고 속도뿐 아니라 저글링처럼 Iscript의 Move로 이동하는 병력과 이동 예측에도 적용합니다. 큰 중첩에서 정수 곱셈이 넘치는 경우를 포화 처리합니다. 정점 확대와 모델 연결 검사는 실제 화면 외관 검증이 아닙니다. HD·SD 애니메이션, 화면 가장자리의 원래 엔진 클리핑과 동시 다수 장판의 실제 FPS는 게임 플레이에서 추가 확인해야 합니다.
